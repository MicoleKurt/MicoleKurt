## `◈` Design Patterns Arc

<div align="center">

| # | Pattern | Category | Description |
|:--:|:--|:--:|:--|
| `01` | [**CommandPattern**](https://github.com/MicoleKurt/CommandPattern) | Behavioral | Encapsulates requests as objects — enables undoable operations and action queuing |
| `02` | [**Adapter-Pattern**](https://github.com/MicoleKurt/Adapter-Pattern) | Structural | Bridges incompatible interfaces — makes legacy and modern systems cooperate cleanly |
| `03` | [**Facade-Pattern**](https://github.com/MicoleKurt/Facade-Patern) | Structural | Simplifies complex subsystems behind a unified high-level interface |
| `04` | [**Prototype Design Pattern**](https://github.com/MicoleKurt/Prototype-Design-Pattern) | Creational | Clone objects efficiently — decouples instantiation from implementation |
| `05` | [**SOLID Design Principles**](https://github.com/MicoleKurt/Solid-Design-Pattern) | Principles | Five foundational OOP rules for long-lived, maintainable code |
| `06` | [**Component Design Pattern**](https://github.com/MicoleKurt/Component-Design-Pattern-) | Structural | Builds modular, reusable component hierarchies for scalable systems |
